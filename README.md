# NewMed: an AI product case study

**Two working healthcare AI prototypes, the SQL discovery trail that justified them, the eval methodology behind them, and the full AI PRD. Built by [Nayan Lal](https://www.linkedin.com/in/nayan-lal).**

> NewMed is a **fictional** practice-management platform. All data is synthetic and generated by code in this repo. No real patient, provider, payer, employer, or client material appears anywhere.

## What this is

I built this to teach myself US medical billing fast and to show, end to end, how I believe AI products should be built:

1. **Start in the data, with SQL.** Eight commented discovery queries over a 6,000-claim synthetic warehouse decide whether to build at all.
2. **Ship an interpretable model.** A 15-weight logistic model a biller can audit, evaluated with a temporal backtest (train on the past, test on the future), AUC 0.853.
3. **Expose the trade-offs as product decisions.** The operating threshold is a slider with live workload and economics, not a data-science constant.
4. **Gate the rollout with evals and keep the human in the loop.** Offline backtest, gated alpha with 100% human review, one-click override that becomes training data.

## The products

| | Denial Prevention Co-Pilot | Practice Ops Bottleneck Analyzer |
|---|---|---|
| Problem | 10-15% of claims denied, $25-118 rework each, ~half written off | Practices don't know where staff hours go |
| Approach | Pre-submission denial risk scoring with predicted reason and one-click fix | Task-event mining with per-practice bottleneck ranking and automation ROI |
| Live route | `/copilot/` | `/ops/` |
| Source | [`products/denial-prevention-copilot`](products/denial-prevention-copilot) | [`products/ops-bottleneck-analyzer`](products/ops-bottleneck-analyzer) |

Each product folder is a complete standalone project: data generator, SQL analysis, model training (where applicable), app, and docs (PRD, discovery trail, eval methodology, glossary, demo script).

## Repo layout

```
index.html          the case-study hub (products, method, gated AI PRD, about)
copilot/  ops/      deployed product apps (assembled from products/*/app)
prd/                the AI PRD, gated behind a request form / access code
assets/             CV download
products/           full source of both products, pipelines and docs included
build_site.py       copies products/*/app into the site routes
```

## Run locally

Python 3 stdlib only, no installs:

```bash
python3 products/denial-prevention-copilot/run_pipeline.py   # optional: regenerate all data
python3 products/ops-bottleneck-analyzer/pipeline.py         # optional: regenerate ops data
python3 build_site.py                                        # assemble site routes
python3 -m http.server 8803                                  # open http://localhost:8803
```

## Honest limitations

Synthetic data flatters models: the AUC demonstrates the method, not real-world accuracy. Single-line claims only. The PRD gate is client-side lead capture, not security. A production system needs the HIPAA controls described in the TRD, which a prototype does not implement.
